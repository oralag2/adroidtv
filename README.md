# KinoTV

Android TV / Google TV застосунок на Kotlin і Jetpack Compose for TV. Назва репозиторію — `adroidtv`, назва застосунку — **KinoTV**, ідентифікатор пакета — `ua.kinotv.app`.

Технічне завдання: [docs/SPECIFICATION.md](docs/SPECIFICATION.md). Інструкції перевірки: [docs/TESTING.md](docs/TESTING.md).

## Поточні можливості

- Інтерфейс українською мовою, навігація пультом, каталог фільмів і серіалів із переходом до наступної сторінки.
- Пошук, картки з постерами, сторінка фільму з доступними описом, роком, жанрами й рейтингом.
- Отримання роздач зі сторінки завантаження UA Kino через оголошений сайтом AJAX-запит, а також прямих HTTPS-посилань на торрент-файли.
- Завантаження торрент-файлу BitTorrent v1 з індикацією прогресу, перевіркою bencode-структури, обмеженням 5 МіБ та історією збережених файлів.
- Передача збереженого файлу встановленому торрент-застосунку через системний вибір застосунку.
- Зміна базового домену в налаштуваннях зі збереженням після перезапуску.
- Стани завантаження, порожніх результатів і помилок із повторною спробою.

## Межі цієї версії

У версії **0.2.0** код репозиторію перевірено на живому UA Kino: для «Матриці» отримано п’ять реальних роздач і посилання на програвач. Розмітка джерела не є стабільним API й може змінюватися. Наскрізне відтворення на телевізорі та передача реального торрент-файлу зовнішньому клієнту ще потребують перевірки.

Для роздач застосунок переходить за посиланням `torentdownload` на `download.html`, читає параметри запиту `engine/ajax/toloka.php` і обробляє таблицю відповіді. Для динамічного програвача використовується запит `engine/ajax/playlists.php`, який оголошує сайт. Відсутні дані не підставляються. Якість, розмір, мови та кількість сідерів відображаються лише за наявності відповідних даних у джерелі.

Кнопка «Дивитися онлайн» відкриває вбудований екран KinoTV: прямі відеофайли й HLS відтворює Media3 ExoPlayer, HTML-програвач джерела працює через Android System WebView. Встановлений браузер не потрібен. Для HTML-програвача на пристрої має бути доступний Android System WebView. Програвач підтримує повернення назад, повноекранний режим, повідомлення про помилки та повторну спробу. Його роботу з реальним відео необхідно перевірити на емуляторі та телевізорі.

Під час хмарної перевірки запит самого `.torrent` повернув HTTP 403 із перевіркою браузера Cloudflare, хоча список роздач працював. Застосунок показує цю причину окремо й не зберігає HTML як торрент. Повний торрент-рушій і завантаження відео не реалізовані; сумісність із конкретним торрент-клієнтом, зокрема TorTracker, потребує перевірки на пристрої.

## Відкриття в Android Studio

Потрібні Android Studio з підтримкою Android Gradle Plugin 8.13.x, Android SDK Platform 36 та SDK Build-Tools 35.0.0. У хмарі також установлені Build-Tools 36.0.0. Мінімальна версія Android на пристрої — **Android 11 / API 30**.

1. Завантажте репозиторій або клонуйте його:

   ```bash
   git clone https://github.com/oralag2/adroidtv.git
   cd adroidtv
   ```

2. В Android Studio виберіть **Open** і відкрийте корінь репозиторію, де розташований `settings.gradle.kts`.
3. У **Settings → Build, Execution, Deployment → Build Tools → Gradle** виберіть Gradle JDK **17 або 21**. У хмарному середовищі налаштовано JDK 21. Використовуйте повний JDK із `javac`.
4. Через **SDK Manager** установіть Android SDK Platform 36, SDK Build-Tools 35.0.0 та Android SDK Platform-Tools. Виконайте **Sync Project with Gradle Files**.
5. У **Device Manager** створіть пристрій Android TV / Google TV із системним образом API 30 або новішим. Або підключіть Xiaomi TV Box S 3rd Gen через ADB.
6. Виберіть конфігурацію `app` і запустіть застосунок кнопкою **Run**.

`local.properties` з локальним шляхом до SDK Android Studio створює самостійно. Не додавайте його, ключі підпису та локальні кеші до Git.

## Збірка та перевірки з термінала

Запускайте команди з кореня репозиторію. Потрібні правильно налаштовані `JAVA_HOME` і Android SDK; шлях до SDK можна задати через `ANDROID_HOME` або локальний `local.properties`.

```bash
./gradlew --max-workers=4 assembleDebug testDebugUnitTest lintDebug
```

У Windows використовуйте `gradlew.bat` замість `./gradlew`.

Gradle Wrapper зафіксований на версії 8.13 із SHA-256 перевіркою дистрибутива. Версії плагінів і залежностей задані в Gradle-файлах проєкту. Для першої синхронізації потрібен доступ до Google Maven, Maven Central, Gradle Plugin Portal та серверів дистрибутива Gradle.

Результат debug-збірки:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Встановлення на підключений телевізор або емулятор:

```bash
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n ua.kinotv.app/.MainActivity
```

Для кількох підключених пристроїв додавайте `adb -s SERIAL`. Debug APK призначений для розробки; випуск підписаного release APK налаштовується окремо.

## Структура

Проєкт містить один Gradle-модуль `app`:

| Пакет / файл | Відповідальність |
|---|---|
| `MainActivity` | Точка входу, підключення UI та системних переходів |
| `KinoViewModel` | Стан екранів, запити, повторні спроби, прогрес завантаження |
| `ui` | Екрани Compose for TV та керування фокусом |
| `data/model` | Моделі фільмів і роздач |
| `data/repository` | Каталог, пошук і завантаження сторінок через OkHttp |
| `data/parser` | Перетворення HTML на моделі через Jsoup |
| `download` | Перевірка, збереження й передача торрент-файлів |
| `playback` | Вбудований екран Media3 / WebView, перевірка адрес програвача |
| `settings` | Перевірка домену та збереження налаштувань |
| `network` | Сесійні HTTP cookies |

Каталог і пошук використовують базовий HTTPS-домен із налаштувань. Редиректи запитів джерела перевіряються й обмежуються тим самим origin — схемою, хостом і портом. Завантаження торрентів з іншого origin поки не підтримується. HTTPS-перевірка сертифікатів увімкнена.

Торрент-файли та їхня історія зберігаються в приватній теці застосунку. Для зовнішнього клієнта створюється `content://` URI через `FileProvider` із дозволом на читання; доступ до всього сховища не запитується. Очищення даних або видалення застосунку видаляє ці файли.

Тести на JVM перевіряють окремі компоненти. Працездатність інтерфейсу пультом, актуальність джерела й відкриття файлу в зовнішньому клієнті необхідно перевірити на емуляторі та Xiaomi TV Box за [контрольним списком](docs/TESTING.md).
