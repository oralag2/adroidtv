# Перевірка KinoTV

Цей документ описує команди й ручні перевірки. Наявність пункту в списку не означає, що його вже виконано.

## Версія 0.2.0 — 26.10.2026

`assembleDebug`, `testDebugUnitTest` і `lintDebug` завершилися успішно: 60 тестів, 0 помилок, 0 пропущених; Lint — 0 помилок і 12 попереджень. Debug-підпис APK перевірено через `apksigner`.

Перевірка живого джерела через скомпільований `UaKinoRepository`: сторінка «Матриці» → AJAX-програвач → сторінка завантаження → POST списку роздач. Отримано п’ять роздач і HTTPS-посилання на програвач; `Referer` кожної роздачі відповідає сторінці завантаження.

Спроба отримати реальний дескриптор `/download/711542/torrent/` у цій хмарі повернула HTTP 403 із перевіркою браузера Cloudflare. Це окремий результат від успішного отримання списку роздач. Відтворення відео й інтеграція із зовнішнім торрент-клієнтом на пристрої ще не перевірені.

Живий UA Kino, емулятор і фізичний телевізор у цьому запуску не перевірені. Мережевий проксі відхилив звернення до домену; KVM для емулятора у хмарі відсутній. Нижче наведено сценарії для перевірки в Android Studio та на пристрої.

## Автоматичні перевірки

З кореня репозиторію:

```bash
./gradlew --max-workers=4 assembleDebug testDebugUnitTest lintDebug
```

Цілі:

- `assembleDebug` — компіляція та формування debug APK.
- `testDebugUnitTest` — наявні JVM-тести парсингу, перевірки URL, сесійних cookies, торрент-структури й безпечних шляхів до файлів.
- `lintDebug` — статичні Android-перевірки debug-конфігурації.

Звіти після виконання відповідної цілі:

```text
app/build/reports/tests/testDebugUnitTest/index.html
app/build/test-results/testDebugUnitTest/
app/build/reports/lint-results-debug.html
```

Перевіряйте код завершення команди та кількість реально виконаних тестів. Успішні JVM-тести й збірка не підтверджують доступність UA Kino, роботу D-pad або сумісність із зовнішнім торрент-клієнтом.

## Підготовка пристроїв

Перевірте Google TV / Android TV Emulator з API 30 або новішим та фізичний Xiaomi TV Box S 3rd Gen. Для перевірки адаптації потрібні конфігурації телевізійного екрана 1080p і 4K. Використовуйте пульт або емуляцію D-pad; миша не замінює перевірку пульта.

Установіть APK:

```bash
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n ua.kinotv.app/.MainActivity
```

Для кількох пристроїв додайте `-s SERIAL` до `adb`. Для фізичного пристрою ввімкніть параметри розробника й ADB або бездротове налагодження відповідно до прошивки; використовуйте адресу та порт, показані самим пристроєм. Емулятору потрібні локальні можливості віртуалізації. У хмарному середовищі без KVM перевірку запуску на емуляторі не слід вважати виконаною.

Для діагностики збережіть журнал відтворення помилки:

```bash
adb logcat -v time
```

Не публікуйте сесійні cookies або приватні дані з журналів.

## Ручний контрольний список

### Запуск та керування пультом

- [ ] KinoTV відображається в списку TV-застосунків і запускається без аварійного завершення.
- [ ] Фокус видно одразу після запуску. Усі пункти меню доступні стрілками й кнопкою OK.
- [ ] Між меню, картками, кнопками та полями немає пастки фокуса.
- [ ] Обраний елемент чітко виділений на темному тлі.
- [ ] Із каталогу відкривається обрана картка; Back повертає до списку зі збереженою позицією та фокусом.
- [ ] У списку роздач Back спочатку повертає до сторінки фільму, далі — до каталогу.
- [ ] Довгий опис можна прокрутити стрілками вгору й униз, після чого перейти до інших елементів.
- [ ] Текст, кнопки та постери не обрізаються на конфігураціях 1080p і 4K.

### Каталог, пошук та сторінка фільму

- [ ] За доступного джерела показуються справжні назви й постери, а не демонстраційні записи.
- [ ] Перемикання «Фільми» / «Серіали» завантажує відповідний каталог.
- [ ] «Наступна сторінка» додає нові картки без дублікатів.
- [ ] Пошук українською мовою, із пробілами та спеціальними символами передає коректний запит.
- [ ] Поле пошуку можна відкрити пультом, ввести текст екранною клавіатурою та виконати пошук.
- [ ] Порожній запит і запит без результатів мають зрозумілий стан.
- [ ] На сторінці фільму перевірені назва, рік, опис, жанри й рейтинг щодо відповіді джерела; відсутні дані не вигадуються.
- [ ] «Дивитися онлайн» відкриває вбудований програвач, зокрема на TV без встановленого браузера.
- [ ] HTML-програвач через WebView відтворює реальне відео, підтримує пульт, повноекранний режим і повернення Back.
- [ ] Прямий HLS або відеофайл відтворюється Media3; пауза, продовження та перемотування працюють із пульта.
- [ ] Після виходу з програвача звук припиняється; повторне відкриття й повернення з фону не призводять до аварійного завершення.

### Роздачі та торрент-файли

- [ ] Роздачі відповідають реальним посиланням у HTML джерела. Метадані перевірені щодо сторінки, а відсутні мови чи сідери не підставляються.
- [ ] Для фільму з `torentdownload` і `download.html` застосунок отримує список через AJAX; для «Матриці» результат відповідає живій таблиці джерела.
- [ ] Справжнє повідомлення сайту «роздач не виявлено» відрізняється від мережевої помилки; кнопка «Оновити роздачі» дозволяє повторити запит.
- [ ] Коректний `.torrent` із того самого origin завантажується; показуються прогрес і повідомлення про збереження.
- [ ] У «Завантаженнях» з’являється запис із назвою, датою, розміром і кнопкою відкриття.
- [ ] Після повного перезапуску збережений файл та історія доступні.
- [ ] На пристрої зі встановленим сумісним торрент-клієнтом системний вибір застосунку передає файл, а клієнт справді читає його.
- [ ] Для TorTracker, якщо він використовується, перевірено підтримку MIME `application/x-bittorrent` і `content://` URI; відмінності протоколу інтеграції записані окремо.
- [ ] На пристрої без торрент-клієнта відсутнє аварійне завершення; Android або застосунок повідомляє про відсутність сумісного обробника.
- [ ] HTML замість торренту, порожній, обрізаний, некоректний або завеликий файл не потрапляє до історії успішних завантажень.
- [ ] HTTP-посилання, редирект на інший origin або локальну адресу відхиляються з повідомленням.
- [ ] Переривання мережі під час завантаження не залишає запису про успіх; повторна спроба можлива.

Завантаження `.torrent` не означає завантаження відео. Перевіряйте отримання дескриптора та його передачу клієнту окремо від подальших дій зовнішнього клієнта.

### Налаштування та збої

- [ ] У налаштуваннях зберігається коректна базова адреса на зразок `https://uakino.best/`.
- [ ] Після зміни домену нові каталог, пошук та сторінки використовують нову адресу.
- [ ] Після `adb shell am force-stop ua.kinotv.app` і повторного запуску домен залишається збереженим.
- [ ] HTTP, адреса з логіном, шляхом, параметрами чи локальним доменом відхиляється без втрати попереднього налаштування.
- [ ] Вимкнення мережі, таймаут, HTTP 403/404/429, перевірка браузера та змінена HTML-розмітка дають видиму помилку.
- [ ] «Повторити» виконує нову спробу після відновлення доступу.
- [ ] Швидке перемикання розділів або повернення Back під час запиту не показує дані попереднього екрана на новому.
- [ ] Довге повідомлення можна прочитати пультом і закрити кнопкою або Back.

## Що залишається непідтвердженим

Доступ до каталогу, сторінок і списків роздач UA Kino у повторній перевірці працював. Завантаження самого торрент-файлу зупинилося на перевірці браузера Cloudflare (HTTP 403). Цей результат не встановлює, яку відповідь сайт поверне на вашому пристрої.

Для завершення MVP із ТЗ потрібно перевірити реальне відтворення через вбудований програвач і передачу справжнього торрент-файлу сумісному клієнту на Google TV і Xiaomi TV Box. До завершення цих перевірок не позначайте повний MVP готовим.

Для кожної знайденої помилки записуйте модель пристрою, версію Android, версію APK, базовий домен, послідовність дій, очікуваний і фактичний результат та журнал. Відокремлюйте збій коду від недоступності джерела або відсутності зовнішнього застосунку.
